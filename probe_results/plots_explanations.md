# Plot Explanations

This note explains each output generated by:

```bash
python3 plot_results/analyze_results.py
```

All figures are written as vector PDFs to:

- `plot_results/output/figures/*.pdf`

## What “Normalization” Means Here

`raw` metrics score the model's direct label output as-is.

`normalized` metrics first map/clean the model output into the target label space (`tool_call`, `request_for_info`, `cannot_answer`, `direct`) and then score. This handles formatting/alias mismatches so the metric reflects decision quality instead of string-format noise.

Interpretation:
- Large positive `normalized - raw` means post-processing fixed many output-format mismatches.
- Small gap means the model already outputs clean labels.
- Negative gap means normalization logic hurt that run (rare, but important to check).

For probe-layer runs, there is no separate raw-vs-normalized decoding step for the probe classifier, so probe rows are included in plots as decision-quality comparisons, but raw-vs-normalized delta analysis is kept focused on non-probe runs.

`75pct` means the probe at roughly 75% model depth (an intermediate hidden layer between middle and last), not 75% of the data.

## 1) `normalized_accuracy_by_run`

What it shows:
- One bar per run, including probe-layer runs.
- Y-axis is 0-100% normalized accuracy.

How to read it:
- Higher is better overall exact-match performance.

## 2) `normalized_macro_f1_by_run`

What it shows:
- One bar per run, including probe-layer runs.
- Y-axis is 0-100% normalized macro-F1.

How to read it:
- Macro-F1 balances class performance more evenly than accuracy.

## 3) `per_class_accuracy_bar_by_run`

What it shows:
- Grouped bars by run.
- One bar per class (`tool_call`, `request_for_info`, `cannot_answer`) within each run.

How to read it:
- Higher bar means better one-vs-rest class separation for that run/class pair.

## 4) `per_class_precision_heatmap_by_run`

What it shows:
- Per-class precision by run.

How to read it:
- High precision means predictions for that class are usually correct.

## 5) `per_class_recall_heatmap_by_run`

What it shows:
- Per-class recall by run.

How to read it:
- High recall means the run catches most true examples of that class.

## 6) `per_class_f1_heatmap_by_run`

What it shows:
- Per-class F1 by run.

How to read it:
- Best single class-level balance between precision and recall.

## 7) `unsupported_direct_prediction_rate_by_run`

What it shows:
- `direct` prediction rate under raw and normalized scoring for prompting runs.

How to read it:
- Lower is better in this setup because `direct` has zero gold support.

## 8) `normalization_outcome_breakdown_by_run`

What it shows:
- Fraction of examples per prompting run that are:
  - `fixed`
  - `broken`
  - `stay_correct`
  - `stay_wrong`

How to read it:
- More `fixed` than `broken` means normalization helps.

## 9) `normalized_prediction_mix_by_run`

What it shows:
- Predicted-label distribution by run (includes probe-layer runs where available).

How to read it:
- Quickly reveals label bias (over-predicting one class).

## 10) `*_without_probe` variants

Files:
- `normalized_accuracy_by_run_without_probe`
- `normalized_macro_f1_by_run_without_probe`
- `normalized_prediction_mix_by_run_without_probe`

What they show:
- Same plots with probe runs filtered out.

Use case:
- Isolate prompting/fine-tuned model comparisons without probe-layer rows.

## Raw vs normalized change table (LaTeX)

File:
- `plot_results/output/raw_vs_normalized_change_table_latex.txt`

What it is:
- Booktabs LaTeX table with raw, normalized, and delta scores by run.

Important:
- This table is intentionally limited to non-probe runs so deltas represent true normalization effects.
